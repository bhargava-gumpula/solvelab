## 900. night-fix-auth-sync — auth and sync audit fixes (2026-10-05)

Branch `night-fix-auth-sync` from `hotfix-5.1.1`. Six verified audit findings in `lib/auth` and `lib/sync`. Each race was reproduced in a deterministic unit test first, and each test fails on the old code.

- **A crafted `/signed-in/` link signed the visitor out and deleted their shares.** `signInWithGoogleOnSupabase` now records in sessionStorage (`solvelab.auth.returnStarted`) that this tab went to Google, as "link" or "signIn". `completeSupabaseReturnFromLocation` reads and removes that marker. With no marker it only tidies the URL. The identity-taken fallback (withdraw shares, local sign-out, sign in again) also needs a "link" marker and an anonymous session from `getSession()`. This branch has no desktop return handler (`completeSupabaseReturnFromUrl`), so there was nothing else to guard.
- **`error_description` from the URL appeared in a toast.** The return page now shows only the fixed "Google sign-in didn’t finish.", and only for a trip this tab started.
- **A solve saved while a full sync was merging was deleted.** `applySnapshot` deleted every key that was not in the merge, which included rows written after the local read. It is now `mergeIntoLocal`, which reads the local copy, merges and applies in one rw transaction, so no write can land between the read and the apply.
- **Sign-out's "save first" resolved before the latest change was uploaded.** With a push in flight, `pushLocalChanges`/`syncAccountNow` used to return the old promise and start a rerun nobody waited for. They now return a queued push that starts after the in-flight one (`afterInFlight`), so the dialog waits for the push that carries the change.
- **A push during the sign-in decision uploaded an unclaimed copy.** `canSync()` now also needs `syncUid === user.uid`. `startAccountSession` sets that only after `decideAccountStart` says "sync", and clears it when a new sign-in starts. `pushLocalChanges` first waits for a pending decision, so a sign-out during it still saves a copy that is about to be kept.
- **Signing out offline with an expired token kept the Supabase session and took about 25 s.** `signOutAccount` now waits at most 5 s. If supabase-js returns an error, throws or times out, `forgetSupabaseSession()` (lib/supabase/client.ts) removes the `sb-<ref>-auth-token*` keys itself.
- **Tests:** `tests/unit/sync-races.test.ts` (3 tests) and `tests/unit/supabase-return.test.ts` (5 tests; one confirms that this tab's own refused link still falls back). Against the old code: 3/3 and 4/5 fail, the old sign-out test taking 25.6 s. With the fix, all pass.
